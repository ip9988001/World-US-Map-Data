# 🔴 严重 · 数据正确性

> 判断标准：数据可能错/漏，且**下游无法感知**。这类问题不会让 run 变红、不会触发告警。

---

## P1 · NAD 县片覆盖率异常，但账本判 complete ⬜→🔴

**现象**：多个州 `phase=complete` 且 `counties_failed=[]`，但 NAD 县片数远少于该州县数：

| 州 | NAD 县片 / 县数 | 状态 |
|---|---|---|
| GA | 2 / 159 | 🔴 待验证 |
| MS | 1 / 82 | 🔴 待验证 |
| SC | 3 / 46 | 🔴 待验证 |
| LA | 5 / 64 | 🔴 待验证 |
| SD | 7 / 66 | 🔴 待验证 |
| FL | 8 / 67 | 🔴 待验证 |
| ID | 11 / 44 | 🔴 待验证 |
| CO | 45 / 64 | 🟡 待验证 |
| MN | 55 / 87 | 🟡 待验证 |
| NV | 0 / 17 | ⬜ 上游确无覆盖（已探针验证） |
| NH | 0 / 10 | ⬜ 上游确无覆盖（已探针验证） |
| HI | 0 / 5 | ⬜ 上游确无覆盖（已探针验证） |

**根因（待确认，两个候选）**：
1. NAD 是按机构自愿申报的库，一个县的数据可能挂在"州级机构"或邻近机构上，按县 polygon 查询命中率低
2. 我们的县 polygon 查询/BBox 构造对某些县失效（如县界多边形获取失败后退化为 envelope + PIP）

**为什么严重**：MANIFEST.shards 只记 NAD 县片，下游（二仓）看 MANIFEST 会认为"这个州的 NAD 就这么多"，**永远不会知道可能漏了 150+ 个县**。且 `counties_failed` 为空，账本上一点痕迹都不留。

**处置**：用 `nad_preflight.py` 的逐县模式对 GA/FL/SC/MS/LA/SD 逐县 `returnCountOnly`，把"上游真无数据"和"我们查询漏了"分开。
- 探针有数据 → 我们的抓取逻辑问题，需修县 polygon 查询
- 探针也是 0 → 与 NV/NH 同性质，应显式写 `nad_no_coverage` 声明

**证据**：`raw-US-GA-v1` 的 STATUS.json —— `expected` 159 县、`done` 2 县、`counties_failed=[]`、`phase=complete`。

## P2 · OR 的 OA 缺 1 个源，重跑未补上 🔴

**现象**：`content-audit` 报 `OR OA 缺 1 个源（上游 38 / 已发 37 / 空包 0）`，持续多轮。

**根因（待确认）**：可能 ① 断点续传把该源判为"已完成"跳过；② 上游本身撤了该源但首页计数未更新；③ 该源下载持续失败被静默跳过。

**为什么严重**：与 2026-10-20 的 MN 事故（上游 66 源只发 60 源）同性质——**run 是 success、gate 通过、无人告警**。

**处置**：拉 OR 的 OA 资产名与上游源列表做差集，定位具体是哪个源；若是静默失败，需在 OA 抓取里把"失败源"写入 STATUS 并让门禁感知。

**证据**：run 39739822815 / 39801205569 的 content-audit 输出。

## P3 · NAD 上游间歇性拒服务（超时/400）🟡

**现象**：连续 3 次 `returnCountOnly`（DE 小框）：**2 次 40 秒超时（http=000）、1 次成功 7.4 秒**。runner 侧探针同日也报 400。

**根因**：上游 `services.arcgis.com` 间歇性限流/拒绝，与请求方无关（本机与 runner 同时出现）。

**影响**：大州 auto 探针拿不到 count → 按大州处理跳过枚举（兜住了）；但 NAD 的 `objectIds` 批取若也被拒，会直接缺县。

**处置**：已缓解——`--skip-state-ids auto` 的 fallback（count 拿不到按大州处理）+ `_esri_query` 的重试退避 + `content-audit` 事后对账。**未根治**（上游不可控）。

**证据**：2026-10-22 连续探测记录；run 39783296319 的 preflight-upstream 日志。

## P4 · TIGER 上游 WAF 拒页导致缺片被门禁拦截 🟡

**现象**：MI 跑完 230 资产 293 MB，但 TIGER 县 `26063` 的 `tl_2024_26063_addrfeat.zip` 被拒 —— 日志原文「上游返回非 zip（WAF 拒页 / 截断），已重试」→ 缺片 → 门禁 exit 3 拒绝封印。

**根因**：`www2.census.gov` 的 WAF 对高频请求返回 HTML 错误页（不是 zip），现有重试次数不足。

**影响**：单个县拒页会让整州无法封印，浪费 1~6 小时 job。

**处置**：已有"号段包连续失败熔断"机制，但单县拒页仍直接阻断。建议：拒页时增加指数退避重试（3→6→12 秒）+ 记录到 `problem()`，重跑时续传补齐。当前处置是重派 run。

**证据**：run 39737647272 的抓取日志 + 批次汇总「MI ⚠️ 未封印」。
