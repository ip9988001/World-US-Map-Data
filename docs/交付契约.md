# 一仓交付契约（v1 · 2026-10-20）

> 适用仓库：`ip9988001/World-US-Map-Data`
> 关系：**一仓出账本，二仓适应一仓。** 一仓不为下游改数据，只为下游把账做对。

---

## 0. 一句话定位

一仓只做三件事：**拿全量原始数据 → 按县切片 + gzip → 发布到 Release。**

> **切分与压缩不算加工。** 不清洗、不去重、不合并、不裁剪字段、不改坐标。
> 上游给什么就落什么，只改变"装文件的容器"，不改变文件里的数据。

---

## 1. 四源交付规则（2026-10-20 用户定案：全部按县）

| 源 | 粒度 | 格式 | 命名 |
|---|---|---|---|
| **NAD**（USDOT 联邦地址库） | 县 + 溢出包 | `ndjson.gz` | `NAD-US-<ST>-<fips>-<county>.ndjson.gz` |
| **Overture** | 县（跨经线县拆 `-w`/`-e`） | `parquet`（失败回落 `geojson`） | `OVERTURE-US-<ST>-<fips>-<county>.parquet` |
| **OpenAddresses** | 上游源（city/borough 级，**比县更细**） | `zip` | `OA-US-<ST>-<source>.zip` |
| **TIGER addrfeat**（号段） | 县 | `zip` | `TIGER-US-<ST>-<fips>-addrfeat.zip` |
| **TIGER 边界** | 县 | `geojson` | `TIGER-US-<ST>-county-<fips>.geojson` |

溢出包：`NAD-US-<ST>-OUTOFSTATE.ndjson.gz`（州 bbox 内、县界外的门牌，**不裁剪**）

**为什么 OA 不按县切**：上游发布的单位就是 city/borough，比县更细。按县切必须拆 zip 再按坐标重新归属，那是二次加工，违反"原始"原则。直接原样发布即为最细粒度。

---

## 2. 命名正则（gate 第七把锁强制，不符合即禁止发布）

```regex
NAD 县片      ^NAD-US-<ST>-\d{5}-[A-Za-z0-9_]+\.ndjson\.gz$
NAD 溢出包    ^NAD-US-<ST>-(OUTOFSTATE|OVERFLOW)\.ndjson\.gz$
Overture     -<ST>-\d{5}-     必须出现
TIGER addrfeat -<ST>-\d{5}-   必须出现
```

---

## 3. 账本（MANIFEST.json）必备字段

| 字段 | 含义 | 硬要求 |
|---|---|---|
| `scope` | 州 / ISO / bbox / 县清单 | 必填 |
| `assets[]` | 每个资产的 `path` / `bytes` / `sha256` / `sha256_head` | **必须覆盖 Release 实物**，宁缺勿编 |
| `shards[]` | `kind`(county/overflow) / `file` / `fips` / `county` / `rows` | `file` **必须是纯文件名**（不带路径） |
| `row_counts` | 文件名 → 行数 | 与 shards 一致 |
| `reference_check` | `counties_total/ok/empty/failed` + `three_number_check` | 县级核验为准 |
| `completeness` | 四源「上游声明 vs 本地实得」 | 逐源给出 |
| `integrity` | `sha256` / `algo` / `sha256_head` / `bytes` | **必须是真哈希**（排除 integrity 字段 + sort_keys），不是说明文字 |
| `volume` | 分卷信息（仅分卷时非 null） | `index` / `total` / `state_total_counties` / `this_volume_counties` / `fips_range` |

### 记账三铁律

1. **上传即记账**：任何资产上传成功立刻写 `fx.meta`，MANIFEST 生成时不可只遍历 `fx.files`
2. **实物优先**：账本 = 本地 ∪ 本轮记账 ∪ STATUS ∪ 远端实物，四源并集
3. **账实必对**：`len(assets)` 应等于 Release 资产数 − 3（MANIFEST/STATUS/RELEASE_NOTES）

## 4. 分卷规则（单 release 资产上限 1000）

| 条件 | 动作 |
|---|---|
| 预估资产数 = 县数×4 + OA源数 + 3 ≤ 900 | 单卷，tag = `raw-US-<ST>-v1` |
| > 900 | 分卷：`--volume 1/2`、`2/2`，tag 自动加 `-pN` |

**分卷三约束**（已验证 S14 场景）：
1. 按县 `fips` 排序均分，每卷只做本卷的县
2. **分卷不产溢出包**（否则 p1/p2 会各自把对方的县再拉一遍 = 双倍数据）
3. 每卷独立 MANIFEST / 独立封印，`three_number_check.applicable = false`

当前只需 TX（254 县 ≈ 1172 个资产）。

---

## 5. 发布门禁（7 把锁）

| # | 锁 | 阻断条件 |
|---|---|---|
| 1 | 源状态 | 必需源缺失 / 状态异常 |
| 2 | 覆盖对账 | 已取行数 ≠ 官方 count（县级模式下按县核验为准） |
| 3 | TIGER 半载包 | `.dbf` 记录数 ≠ `.shx` 记录数 |
| 4 | ISO 州码 | 州码不在 ISO 3166-2 注册表 |
| 5 | **县级内容断言** | `counties_ok = 0`（0 个真县片不许封印） |
| 6 | **分片压缩** | county_shards 模式下存在未压缩 `.ndjson`，或无任何 `.ndjson.gz` |
| 7 | **命名契约** | NAD/OVERTURE/addrfeat 名字里缺州码或县级 fips |

封印点还有一次独立复检（不信任单点 gate）：`counties_ok = 0` → 拒绝上架 MANIFEST（exit 6）。

---

## 6. 禁止项（违反即数据作废）

- ❌ 清洗（补全、格式化、去空白以外的任何改写）
- ❌ 去重（跨源、跨县、县内一律不去重）
- ❌ 合并（多源合成一行、多县合成一文件）
- ❌ 裁剪（按属性或空间过滤掉行；BBox 天然含邻州门牌，如实保留计入溢出包）
- ❌ 未压缩 `.ndjson` 裸件上架
- ❌ 整州单文件冒充县片

---

## 7. 下游（二仓）消费约定

1. tag 模式 `raw-US-<ST>-v1*`（分卷时匹配 `-p1`/`-p2`）
2. 读 `MANIFEST.shards[]`，按 `fips` 匹配（跨经线县会有 `-w`/`-e` 两片，按 fips 聚合）
3. 只信 `shards[]` + `assets[]`，**不需要**猜文件在哪
4. `counties_empty` 是合法状态（如 HI 无 NAD 覆盖、NH 全在溢出包）
5. 见到 `volume` 字段 → 说明该州分卷，需拉齐所有 `-pN` 再合并
